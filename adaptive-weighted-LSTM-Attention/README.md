# Adaptive-weighted LSTM–Attention

PJM(COMED) 하루 전 전력가격 예측에서 **평상시 성능은 유지하면서 가격 급변 구간의 대형 오차를 줄이는** 실험이다. 처음에는 잔차 보정 모델(CaRe-LSTM)을 계획했으나 진단 결과 보류했고, 기본 LSTM(A)과 사례 어텐션 모델(C)을 국면에 따라 다른 비율로 결합하는 **게이트형 결합**으로 전환했다.

## 이름 대응

| 이 폴더 | 기존 README·결과 폴더 | 내용 |
| --- | --- | --- |
| LSTM | A | 과거 168시간 가격·수요 예보 + 목표일 수요 예보 → 24시간 가격 |
| CaseAttn | C | LSTM + 검색한 과거 유사일의 특징·실제 가격에 대한 어텐션 |

두 모델 모두 기존 스크립트(`train_01_baseline.py`, `train_02_bc.py`)와 같은 구조·학습 순서로 옮겼고, `split2_2018`에서 기존 결과를 소수점까지 재현한다(seed 42: A MAE 4.3780, C MAE 4.0736).

## 실험 경과와 결과

### 1단계: 유사일 평균 잔차 보정 (Res-kNN)

> ŷ = ŷ_LSTM + α · (유사 과거일 k개의 OOF 잔차 평균), 잔차 = 실제 − 예측

- 학습 기간 잔차는 시간순 fold 모델(2014·2015·2016 블록)로 만든 학습 외(OOF) 잔차를 쓴다.
- 유사일 기준: LSTM 특징(코사인) 또는 예측 시점 국면 특징(전날 평균·변동성, 수요 예보 변화 등). k와 α는 검증 RMSE로 선택한다.
- 대조군: 무작위 과거일 평균, Ridge 회귀.

| 모델 | 2018 MAE | 2018 RMSE | 2018 급락일 MAE | 2017 MAE | 2017 RMSE |
| --- | --- | --- | --- | --- | --- |
| LSTM | 4.23 | 7.31 | 33.2 | 3.13 | 4.81 |
| Res-kNN (LSTM 특징) | 4.20 | 7.34 | 33.6 | **3.01** | **4.74** |
| Res-kNN (국면 특징) | 4.19 | 7.31 | 33.0 | 3.07 | 4.77 |
| 무작위 과거일 | 4.23 | 7.31 | 33.2 | 3.13 | 4.81 |
| Ridge | 4.23 | 7.31 | 33.2 | 3.10 | 4.80 |

- 2018: 검증에서 α가 0~0.25로 선택되어 사실상 보정이 없었고, 급락일 오차도 그대로였다.
- 2017: 평상시 편향이 보정되어 MAE가 약 4% 줄었다(유의).
- 무작위 과거일은 두 분할 모두 α = 0. 보정 효과는 유사일 검색에서 나온다.

### 진단: CaRe-LSTM(잔차 어텐션)을 보류한 이유

학습 기간(2014–2016)의 급락일 11일에서 유사일 평균 잔차가 실제 잔차를 맞히는지 확인했다(테스트 미사용, `scripts/04_diagnose_crash.py`).

| 그룹 (전날 고가격) | 일수 | 실제 잔차 평균 | 유사일 평균 잔차 | 부호 일치율 | 보정 전 → 후 MAE |
| --- | --- | --- | --- | --- | --- |
| 급락 | 11 | −13.9 (과대예측) | **+14.9** | 0.51 | 40.7 → 41.3 |
| 고가격 유지 | 13 | +74.0 (과소예측) | +13.5 | 0.69 | 87.7 → 77.2 |
| 평상시 | 1,055 | −1.4 | −1.6 | 0.70 | 4.95 → 4.40 |

(유사일 10개, LSTM 특징, ±7일 제외의 가장 유리한 조건)

1. **급락일에는 보정 방향이 반대다.** 급락일과 가장 비슷한 날은 고가격 지속일이었고, 그날 모델은 크게 과소예측했다. 예측 시점에는 두 경우가 구분되지 않는다. 수요 예보 변화만으로 고가격일 안에서 검색해도 부호 일치율은 0.27~0.49였다.
2. **잔차는 그것을 만든 모델에 따라 성질이 다르다.** 2014년 잔차는 1년치만 학습한 fold 모델에서 나와 극한 가격을 일관되게 과소예측하지만, 최종 모델은 급등 뒤 과대예측한다(2018-01-06).

이웃 자체가 반대 방향이면 유사도 가중(어텐션)으로도 해결되지 않고, 급락 사례가 11개뿐이라 학습형 잔차 모델은 과적합 위험이 크다. 그래서 잔차 기반 CaRe-LSTM은 보류했다.

### 게이트형 결합 제안

> ŷ = α · ŷ_LSTM + (1 − α) · ŷ_CaseAttn

- **C는 국면에 따라 성능이 갈린다.** 2018에서는 RMSE가 A보다 낮지만(6.59 vs 7.31), 급변이 없는 2017에서는 MAE가 A보다 유의하게 높다(3.30 vs 3.13).
- **α를 상수로 학습하면 두 국면을 동시에 만족시키지 못한다.** 검증 구간으로 맞춘 α는 0.53~0.82로 A 쪽에 치우친다(검증 연도에 급변이 없음). 2017에서는 가장 좋지만 2018 RMSE는 C보다 나쁘다(6.78).
- 따라서 α를 국면에 따라 바꾸는 게이트가 필요하다.

### 규칙 기반 게이트

> α_d = 0 (전날 가격 변동성 > 학습 기간 90% 분위수), 그 외 0.5

두 값은 실험 전에 고정했고 튜닝하지 않았다. C만 쓴 날은 2018 테스트 33일, 2017 테스트 17일.

| 모델 | 2018 MAE | 2018 RMSE | 2018 하루 오차 상위 5% | 2018 급락일 MAE | 2017 MAE | 2017 RMSE |
| --- | --- | --- | --- | --- | --- | --- |
| LSTM (A) | 4.23 | 7.31 | 17.43 | 33.2 | 3.13 | 4.81 |
| CaseAttn (C) | 4.13 | 6.59 | **14.59** | **26.2** | 3.30 | 4.96 |
| 고정 α (검증 학습) | 4.02 | 6.78 | 15.46 | 30.3 | **3.00** | **4.67** |
| **규칙 게이트** | **3.99** | **6.58** | 14.85 | **26.2** | 3.03 | 4.69 |

| 비교 | 2018 | 2017 |
| --- | --- | --- |
| 게이트 vs A | 유의하게 좋음 | 유의한 차이 없음 |
| 게이트 vs C | 유의한 차이 없음 | 유의하게 좋음 |

- 2018에서는 C의 이득을 유지하고, 2017에서는 C의 손해를 피했다. 두 분할 모두 A와 C 어느 쪽보다도 유의하게 나쁘지 않은 유일한 모델이다.
- 민감도: 분위수 75%·95%, 평소 비율 0.25·0.75에서도 2018에서 A보다, 2017에서 C보다 좋았다(평소 비율 0.25만 2017에서 A보다 유의하게 나쁨).

### 한계

- 게이트 아이디어("1월에는 C, 평상시에는 반반이 최적")는 2018 테스트 예측을 보고 얻었다. 기준값은 미리 고정했지만 2018 결과는 완전히 독립적인 검증이 아니며, 2017 분할이 상대적으로 독립적인 근거다.
- 2017에서 게이트 MAE는 seed 평균 예측 기준 A보다 1.3% 높고(유의하지 않음), 신뢰구간 상한은 +3.6%다.
- 2018 테스트의 급락일은 2일뿐이다.

### 다음 단계: 학습형 게이트 (예정)

α_d = sigmoid(w · x_d + b)인 로지스틱 게이트. 결합 예측의 제곱오차를 최소화하도록 학습하며, A와 C의 학습 외(OOF) 예측(2014–2016 fold + 검증 연도)이 필요하다. 입력은 전날 변동성, 최근 가격 수준 변화, 수요 예보 변화, 두 모델 예측 차이, C의 어텐션 엔트로피.

## 폴더 구조

```
adaptive-weighted-LSTM-Attention/
├── README.md
├── requirements.txt
├── src/care/
│   ├── data.py          # 데이터 로드, 분할, 표준화, 국면 특징, 평가용 그룹
│   ├── baseline.py      # LSTM(A) 모델·학습
│   ├── case_attn.py     # CaseAttn(C) 모델·학습 (train_02_bc.py 이식)
│   ├── retrieval.py     # 유사일 검색
│   └── metrics.py       # 지표, 블록 부트스트랩
├── scripts/
│   ├── 01_make_oof.py         # LSTM 본 모델 + 시간순 fold 모델, OOF 잔차
│   ├── 02_res_knn.py          # 1단계 잔차 보정과 대조군
│   ├── 03_summarize.py        # seed 요약, 부트스트랩 (--stage res_knn | gate)
│   ├── 04_diagnose_crash.py   # 급락일 진단 (학습 기간만)
│   ├── 05_train_case_attn.py  # CaseAttn 학습
│   ├── 06_gate.py             # 고정 α 결합, 규칙 기반 게이트
│   └── smoke_test.sh          # 짧은 전체 점검
└── results/                   # 실행 결과 (git 제외)
```

데이터는 `../PJM_error_analysis/data/PJM.csv`를 참조한다.

## 실행

```bash
python -m venv ../.venv
../.venv/bin/pip install -r requirements.txt   # CUDA는 pytorch.org의 CUDA용 torch 2.15.0 설치
DEVICE=cuda bash scripts/smoke_test.sh          # 1 seed, 2 에폭 점검
```

전체 실행 순서 (CUDA는 `--device cuda`, 완료된 seed는 건너뜀):

```bash
../.venv/bin/python scripts/01_make_oof.py --device cuda
../.venv/bin/python scripts/02_res_knn.py
../.venv/bin/python scripts/03_summarize.py --stage res_knn
../.venv/bin/python scripts/04_diagnose_crash.py
../.venv/bin/python scripts/05_train_case_attn.py --device cuda
../.venv/bin/python scripts/06_gate.py
../.venv/bin/python scripts/03_summarize.py --stage gate --references LSTM CaseAttn
```

- 위 수치는 맥 CPU에서 얻었다. CPU와 CUDA는 같은 seed라도 결과가 조금 다르므로, 비교표에 들어가는 실행은 모두 한 기기·한 장치에서 한다.
- CUDA 실행은 아직 검증하지 않았다. 먼저 `smoke_test.sh`로 확인한다.
- Windows에서는 WSL에서 실행하거나 `PYTHON` 환경변수로 파이썬 경로를 지정한다.
- 결과와 가중치(`results/`, `*.pt`)는 git에 올리지 않으므로 공유 드라이브에 따로 보관한다.
